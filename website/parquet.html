Versus parquet-go

Parquet is the columnar format most Go programs read and write today, and parquet-go is the Go library for it. This page says how fast vortex-go reads the same rows, from a Vortex file, as parquet-go does from a Parquet file.

What is compared

  • The same 10 million rows of 16 columns, generated from a seed, written once to a Vortex file by vortex-go and to a Parquet file by parquet-go, each with its default settings.
  • Both fill the same Go structs with the rows: vortex.Rows on one side, a GenericReader on the other.
  • Three cases: every column, 3 columns of the 16, and a filter that keeps 1% of the rows. vortex-go filters in the reader, where it skips the parts of the file that have no such row. parquet-go reads the 3 columns of every row and the filter is a test in Go.
  • Each case runs with one thread and with every core, on the same machine, with the two files in the cache of the system.

It is two formats and two libraries at once: a difference says which pair reads these rows faster, not which format is better. The scans of batches, with no struct, and the writes are compared with the Rust implementation, on its page.

Speed

Lower is better. A ratio is our time over the parquet-go time: above 1, we are slower. The numbers are measured on every merge to main and filled in when this site is built.

With and without a mapped file

OpenFile reads each part of the file it needs into memory. OpenMapped maps the file in memory and decodes it where it is, with no copy. Every case that reads is measured both ways. parquet-go has no such mode, it reads the file: its time is the same next to both.

A mapped file is the fastest way to read a local file that the system already has in its cache, which is the case of these measurements. It has limits, which is why it is a function of its own and not the default:

  • It is for a local file: not a network file system, not an object store, not a reader of your own.
  • Nothing may truncate or replace the file while it is read. The system reports a mapped byte it cannot read, a truncated file or a failing disk, by stopping the process, where OpenFile returns an error.
  • The columns of a batch are views of the file: they are not read after Close.
  • On a file that is not in the cache, a mapped read waits for the disk one page at a time, where OpenFile asks for a whole part at once: on slow storage the gain can be a loss.
  • Where the platform cannot map a file, OpenMapped is OpenFile.
