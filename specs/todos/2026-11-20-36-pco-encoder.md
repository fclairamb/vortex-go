# A Pco encoder: `vortex.pco` for numbers in compact mode, and the compact size gate back to 1.10

## Problem

`vortex.pco` is read and never written. It was a decision of the encoders spec
(`specs/done/2026/11/2026-11-20-21-float-string-and-zstd-encoders.md`, "No Pco encoder in
this version"), and `docs/goals.md:71-75` gives its price: in `Compact` the gate is 1.18
in place of 1.10, because the reference codes integers with Pco, which takes their
deltas (`o_orderkey` of `orders`: 1 kB in Pco, 31 kB bit-packed by us). `tpch_orders.compact`
is 1.157 (`testdata/size-ratios.json`).

This spec reverses that decision.

The reference: `vortex.integer.pco` and `vortex.float.pco`, only in compact mode
(`~/code/other/vortex/vortex-btrblocks/src/builder.rs:59-60`), by
`Pco::from_primitive(input, pco::DEFAULT_COMPRESSION_LEVEL, 8192)`
(`schemes/integer/pco.rs:61-70`, `schemes/float/pco.rs:61`), never for `i8` and `u8`
(`schemes/integer/pco.rs:48-51`). The codec is the `pco` crate 1.1.0 (`Cargo.toml:217`).

We have the decoder: `internal/pco` (format 4.1, the wrapped format: a header, a
metadata block per chunk, the pages) and `internal/array/pco.go`.

## Proposal

The file only has to be a valid Pco stream that the reference decodes to the same
numbers. It does not have to be the stream the crate would write.

1. `internal/pco`, the write side of what the package reads (`meta.go`, `page.go`,
   `bits.go`, `delta.go`, `float.go`): a bit writer, the header, the chunk metadata (mode,
   delta encoding, the bins of each latent variable with their weights), and the pages
   (the tANS states, the bin of each number, its offset bits).
2. The choices of the encoder, kept small:
   - mode: classic for integers. For floats classic too, and the float-multiplier mode
     when the values are multiples of one base (prices), found on a sample as the crate
     does;
   - delta: none or consecutive of order 1 or 2, the one with the smallest estimated
     size on a sample;
   - bins: the latents sorted and cut into up to `2^level` bins of about equal weight,
     neighbours merged when that saves bits; `level` is the default of the crate;
   - the tANS table from the weights of the bins, as the format requires it.
3. `internal/encode/pco.go`: `IDPco` and `Pco[T](e, v, nulls) *Node` for the 16, 32 and
   64-bit integers and floats: the valid values, pages of 8,192 values as upstream, the
   metadata `{header, chunks: [{pages: [{n_values}]}]}` (`internal/array/pco.go:19-24`),
   the buffers in the order the decoder reads them, and the validity. An `estimate` twin.
   In `Encodings()` (`internal/encode/node.go:324`).
4. `internal/compress`: an `sPco` candidate for integers and floats when the mode is
   `Compact`, next to zstd (`schemes.go:145-160`, `:191-207`). Not for `i8` and `u8`.
5. `wforce.go`, `forceNumber`: `"pco"`.
6. The size gate: `sizeLimits["compact"]` goes from 1.18 to 1.10 (`size_test.go:26`), and
   the three compact ratios are committed at their new values.
7. `docs/goals.md`: the paragraph on the compact gate (`:71-75`) and the list of what is
   never written. `README.md` "Limits": the last line goes when the OnPair spec is done
   too. `docs/testing.md` section 4 if it names 1.18. `go generate`.

## Tests

- `internal/pco`: write then read with our decoder, seeded, for each type: sorted keys,
  timestamps with a constant step, prices with 2 decimals, random bits, one value, 8,192
  and 8,193 values (a page boundary), 300,000 values (more than one chunk of the decoder,
  `internal/array/pco.go:11`), every value equal, the extremes of the type, NaN and `-0`
  bit-exact.
- Each mode and each delta order is produced by at least one input, and asserted.
- The vectors of `testdata/vectors/` made by the reference (`tools/oracle/pcovectors.py`)
  still decode: the decoder is untouched.
- `estimate` within 10% of the real size.
- Negative: `i8` and `u8` are never Pco. `Default` mode never writes Pco.
- `make interop`: a forced `pco` file per type, with and without nulls, read by the
  reference. The size gate at 1.10 for the six ratios.
- A sorted `i64` key column of 100,000 rows in `Compact` is at most 1.2 times the size
  of the reference's Pco array for the same data (measured once by `make interop`,
  committed as a floor that can only rise).
- `TestWrittenMatchesFiles` (spec 28) meets `vortex.pco`.
- `testing.AllocsPerRun`: 0 allocation per call into reused buffers.
- `go test -fuzz` on the write then read round trip, added to `make fuzz`.

## Open questions

- **How much of the crate's search to port.** The crate also has a lookback delta, a
  convolution delta and an integer-multiplier mode. Recommended answer: none of the
  three at first. Classic and float-multiplier modes with consecutive deltas cover the
  TPC-H and ClickBench columns that cost us today (keys, dates, prices). Add another one
  only if the gate at 1.10 needs it.
