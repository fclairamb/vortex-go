# Variant columns are read, at the row level

## Problem

Edition `core 2026.08.3` added the Variant type and two arrays, `vortex.variant` and
`vortex.parquet.variant`. It is the last logical type with no Go mapping: open decision 3
of `docs/goals.md`. The proposal in `docs/interface.md` is "`any` in a row struct, and
nothing at the column level in the first version".

Upstream paths are in `~/code/other/vortex`.

## Proposal

1. `vortex.variant` (`vortex-array/src/arrays/variant/vtable/`): metadata `{shredded_dtype?:
   DType as protobuf}` (`vtable/mod.rs:52-56`), children: the core storage, then the
   optional shredded array.
2. `vortex.parquet.variant` (`encodings/parquet-variant/src/vtable/`): metadata `{has_value,
   typed_value_dtype?: DType as protobuf, value_nullable}` (`vtable/mod.rs:67-78`),
   children: validity, `metadata` (Binary), `value` (optional), `typed_value` (optional).
   It is the Parquet Variant layout: `metadata` is the key dictionary, `value` the encoded
   value, `typed_value` the shredded part.
3. `internal/variant`: decode one Parquet Variant value from `metadata` and `value` bytes
   into a Go value, following the Parquet Variant encoding spec: null, booleans, the
   integer widths, float, double, decimals, date, timestamps, binary, string, object (keys
   from the dictionary) and array. When a row has a `typed_value`, it wins over `value`,
   field by field for objects.
4. A protobuf `DType` decoder (`vortex-array/proto/dtype.proto`) into the `Type` of
   `schema.go`. It is small and the writer does not need it.
5. **Column level:** `Type().Kind()` is `Variant`. `Null(i)` works. A new accessor,
   `Column.Variant(i) any`, decodes one value. Go values: `nil`, `bool`, `int64`,
   `float64`, a decimal (see the open question), `string`,
   `[]byte`, `time.Time`, `[]any`, `map[string]any`. It allocates, and the doc says so.
6. **Row level** (used by the rows spec, written after this one): a field of type `any`
   takes a Variant column.
7. The oracle's canonical hash for Variant, left open in the oracle spec: the hash of the
   value rendered as canonical JSON (sorted keys, numbers as the reference prints them).
   Add it to `docs/testing.md`, to `tools/oracle` and to `internal/testutil`, and
   regenerate `extra/variant.expected.json`.
8. `docs/goals.md`: open decision 3 moves to "Decisions taken" with the answer adopted
   below. `docs/interface.md`: the Variant row of the table and `Column.Variant`. Update
   `api.txt`.

## Tests

- The harness: `extra/variant` passes, with a shredded and an unshredded column.
- `internal/variant`: one hand-encoded value per primitive type, nested objects and
  arrays, an object with 300 keys (offsets wider than one byte), an empty object, a null
  inside an array.
- Damage: a value cut at every byte, a key id past the dictionary, an offset past the
  value, nesting deeper than the depth limit. Errors, no panic.
- The protobuf `DType` decoder: one case per kind, built by hand.

## Open questions

- **The Go mapping of Variant** (open decision 3 of `docs/goals.md`). Recommended answer:
  the proposal of `docs/interface.md`, plus `Column.Variant(i) any` at the column level so
  the column API is not blind to the type. `any` holds `nil`, `bool`, `int64`, `float64`,
  `string`, `[]byte`, `time.Time`, `[]any` and `map[string]any`.
- **Decimals inside a Variant.** A `vortex.Decimal` has no scale of its own. Recommended
  answer: a small exported struct `VariantDecimal{Value Decimal; Scale int}` for that one
  case, rather than losing the scale or converting to `float64`.

## Resolved open questions

- **The Go mapping of Variant:** the proposal of `docs/interface.md`, plus `Column.Variant(i) any`; `any` holds `nil`, `bool`, `int64`, `float64`, `string`, `[]byte`, `time.Time`, `[]any` and `map[string]any`. (autopilot: recommended answer)
- **Decimals inside a Variant:** an exported struct `VariantDecimal{Value Decimal; Scale int}`. (autopilot: recommended answer)
