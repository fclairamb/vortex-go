# A small file is no bigger than its Parquet twin

## Goal

Under `Compact`, the 3-row file of dbbat's archive (`dbbat_test.go`, `dbbatRows(3, 2, false)`)
is no bigger than the 2,068 bytes parquet-go 0.32.1 with zstd writes for the same rows, the
large cases do not grow, and the reference reader still reads every file.

## Why

dbbat archives the captured rows of a connection in one file, and most connections capture
few rows. After `2026-11-22-01-compact-json-text-size`, large files beat Parquet, but the
3-row file is 5,408 bytes under `Compact` against Parquet's 2,068: the values are about 270
bytes, the rest is structure.

Breakdown of the 5,408 bytes (parsed from the postscript and the footer):

| Part | Bytes | What is in it |
|---|---|---|
| Magic | 8 | |
| Column segments | 1,856 | 6 flat segments of 3 rows; the root array of each carries its `ArrayStats` (a uuid's min and max are list scalars of 77 bytes each) |
| DType | 708 | 6 fields; each of the 3 uuids has its own extension, fixed-size list and `u8` tables, each table its own vtable |
| Layout | 304 | |
| File statistics | 1,912 | the legacy `field_stats` and the aggregates, the same values twice |
| Footer | 416 | |
| Postscript and trailer | 176 | |

## Implementation

Each step measured on the 3-row file under `Compact`; kept only when it pays.

1. **One vtable per shape** (`internal/flatbuf/builder.go`, every mode). `EndTable` looks for a
   vtable already written with the same bytes and points the table to it (a negative
   `soffset`), as the reference flatbuffers builder does. 5,408 → 5,016.
2. **A dtype table per distinct type** (`writer.go`, `dtypeStruct`, every mode): a field whose
   type equals an earlier field's points to that field's table. A flatbuffer may point twice
   to a table; the three uuids share one. 5,016 → 4,840.
3. **No statistics on a chunk under `Compact`** (`wcol.go`, `wcompress.go`): the root array of
   a flat chunk carries none, and they are not computed. A reader prunes with the zones table
   and the file statistics; the reference's flat layout prunes nothing
   (`vortex-layout/src/layouts/flat/reader.rs`, `pruning_evaluation` returns the mask as is).
   4,840 → 3,816.
4. **No file statistics for a file read whole** (`writer.go`, `Writer.fileStats`), under
   `Compact`: when the body written before the statistics plus 16 KiB (a bound on the footer
   and the postscript) fits in the reader's first read (`u16::MAX` bytes,
   `vortex-file/src/open.rs`, `INITIAL_READ_SIZE`), the postscript has no `statistics`
   segment. Such a file is in memory after the first read: its statistics can save no read,
   and they were 1,912 of its bytes. A larger file keeps them. 3,816 → 1,968.

`Default` keeps the chunk and file statistics (it follows the reference's layout); steps 1
and 2 apply to it too.

Left out, measured or estimated:

- Writing only one form of the file statistics (the reference's default is the legacy
  `field_stats` alone): with step 4 a small file has none, and on a large one they are a few
  hundred bytes of megabytes.
- One flat segment for the whole struct when the file is tiny (a `vortex.struct` array in a
  single flat layout, as upstream's synthetic fixtures are): about 300 to 400 bytes less
  (one segment spec, one array message, a layout of one node), but a second write path for
  every column. Not needed for the goal.

## Tests

- `TestDBBatTiny`: the 3-row file under `Compact` is at most 2,068 bytes, and smaller than
  `Default`; a filter still finds its rows.
- `TestDBBatSize` keeps its bounds on the 100k-row cases.
- `TestCompactStatistics`: under `Compact` a chunk has no statistics, a small file has no
  statistics segment and a file over the first read has one; `Default` has both.
- `TestBuilderSharesVTables`: tables of one shape share a vtable and read their own fields.
- `make interop`: the reference reader (0.93.0, the latest, and 0.64.0 / 0.83.0 for
  `core 2025.05.0`) reads every file, the small `Compact` ones included: `dbbat_3_rows_compact`,
  the `type_*` files of 200 rows, `wide_one_row`.

## Resolved open questions

Checked against upstream at 0.93.0 (`~/code/other/vortex`):

- The `statistics` segment is optional: `PostscriptSegment` without `(required)` in
  `vortex-file/flatbuffers/vortex-file/footer.fbs`, `statistics: Option<PostscriptSegment>` in
  `vortex-file/src/footer/postscript.rs:25`, and `layout_reader` (`vortex-file/src/file.rs:89`)
  and `can_prune` (`file.rs:285`) do without. The reference writer omits it itself when asked
  to (`with_file_statistics(vec![])`, `vortex-file/src/writer.rs:316-320` and `:380`). The
  older readers (0.64.0, 0.83.0, for `core 2025.05.0`) open such files: `make interop`.
- The flat layout prunes nothing (`vortex-layout/src/layouts/flat/reader.rs:118-125`,
  `pruning_evaluation` returns its mask). Its writer stores the statistics the array happens to
  have cached (`flat/writer.rs`), it computes none: they are a cache, not a promise of the format.
- Shared vtables are what the reference flatbuffers builder writes (the `flatbuffers` crate
  dedups them), and the verifier follows offsets, it does not forbid a table reached twice.
  `make interop` reads every file with the reference.
- The reference writes the legacy `field_stats` alone by default
  (`write_nested_statistics: false`, `vortex-file/src/writer.rs:117-118`); we write both forms
  (spec 19). With step 4 the small files have neither, so writing one form is left out.
