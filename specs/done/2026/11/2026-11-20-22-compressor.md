# The compressor picks the encodings of each chunk, and our files are at most 10% larger than the reference writer's

## Problem

The encoders exist but nothing chooses between them: `WriteOptions.Compression` is
ignored. Goal 3 of `docs/goals.md`: "the compressor picks encodings per chunk, like the
reference one, and our files are at most 10% larger than the reference writer's on TPC-H
and ClickBench". `docs/testing.md` section 4 makes it a gate: the measured ratio is
committed and can only go down.

Upstream paths are in `~/code/other/vortex`. The reference compressor is the pair
`vortex-compressor` (the engine) and `vortex-btrblocks` (the schemes).

## Proposal

1. `internal/compress`: for one chunk of one column, try the candidate schemes on a
   sample, keep the smallest, then apply it to the whole chunk. A scheme's children (the
   codes of a dictionary, the integers of ALP, the offsets of FSST) are compressed the
   same way, to a depth of 3 (`vortex-compressor/src/scheme/ctx.rs:16`).
2. **Sampling**, as upstream (`vortex-compressor/src/compressor/sample.rs:30-41,135-147`):
   runs of 64 consecutive values, 16 runs at least, about 1% of the chunk, a fixed seed so
   the same input always gives the same file.
3. **Candidates by type**, from `vortex-btrblocks/src/` (one scheme list per type):
   - integers: constant, sequence, then in the order of the reference (`session.rs`): FoR
     then bit-packing, zigzag, bit-packing, sparse, dictionary, run-end, RLE;
   - floats: constant, ALP, ALP-RD, dictionary, sparse when nulls dominate (over 90%), RLE
     (upstream has no run-end scheme for floats);
   - strings: constant, dictionary, FSST; binary: constant, dictionary (upstream has no FSST
     scheme for binary);
   - decimals: byte parts, then as integers. Timestamps: datetime parts, then as integers;
   - booleans and validity: constant or plain. Nested types: the elements, the offsets and
     the sizes of a list are compressed, the validity is not (`structural.rs`).
   Plain is always a candidate: a chunk is never made larger.
4. **Modes** (`vortex-btrblocks/src/builder.rs:46-97`):
   - `Default`: the list above;
   - `Compact`: adds `vortex.zstd` for strings, binary and numbers;
   - `None`: plain arrays, as before.
5. The probe of the dictionary layout (the chunks and zones spec) now asks the compressor
   whether it would pick a dictionary, as upstream does, instead of its fixed 50% rule.
6. **Speed**: the estimates run on the sample only, and a scheme whose estimate cannot
   beat the current best by more than its own overhead is skipped. Compression runs per
   column in parallel, one goroutine per column up to `GOMAXPROCS`. Segments are still
   written in a fixed order, so the output does not depend on scheduling.
7. **The size gate**, in `make interop`: write the TPC-H `lineitem` and `orders` and the
   ClickBench `hits_5k` data (read from the reference's own files in `.cache/fixtures/`)
   in `Default` and `Compact` mode. For each, ratio = our size / the reference file's
   size. The six ratios are committed in `testdata/size-ratios.json`. The gate fails
   above 1.10, and when a ratio is higher than the committed one. `docs/testing.md`
   section 9: "File size ratio" becomes "in place".
8. `docs/goals.md`: the measured ratios, and for compact mode what the missing Pco
   encoder costs.

## Tests

- Determinism: writing the same data twice gives the same bytes, with `GOMAXPROCS` 1 and 8.
- Never larger: for seeded random data of every type, the compressed chunk is not larger
  than the plain one.
- Choice, on data built for it: sorted integers pick FoR and bit-packing, a low
  cardinality string column picks a dictionary, prices pick ALP, a constant column picks
  constant, long runs pick run-end or RLE.
- Round trip in Go and `make interop` on all the data of the earlier writer specs, in the
  three modes.
- The size gate of step 7.
- With `-race`: 8 columns compressed in parallel, 100 runs.
- `testing.AllocsPerRun`: 0 allocation per `Write` once the writer runs, compressor
  included.

## To verify

- The scheme lists and their order in `vortex-btrblocks/src/` at tag `0.93.0`, and the
  thresholds each scheme uses to bow out (minimum run length, maximum distinct ratio).
  Checked: the order is `session.rs`; run-end and RLE bow out under an average run of 4,
  FoR when the smallest value is 0 or it packs no narrower than bit-packing, bit-packing on
  a negative value, zigzag without one, a float sparse unless 90% of the rows are null.
  The dictionary's 50% distinct rule is left to the sample, which measures it. Step 3 is
  fixed to match.
- How the reference compresses the validity and the offsets of nested types. Checked
  (`vortex-compressor/src/compressor/structural.rs`): the elements, offsets and sizes of a
  list are compressed, the validity is kept as it is. Step 3 is fixed to match.
- Whether the dataset rows can be fed to our writer from our own reader without loss
  (every type of those files must round-trip). Checked: `make interop` gives the files we
  write from them to the reference reader with the reference's own hashes, and they match.
